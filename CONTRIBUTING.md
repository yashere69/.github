# Contributing

These are small tools, each maintained by one person. Contributions are welcome. What
helps most, roughly in order:

1. **A bug report with an input that reproduces it.** Most of these tools read files
   people export from somewhere else (WhatsApp, Shopify, chat logs, skill folders), and
   the formats drift. A three-line sample that breaks the parser is worth more than a
   description of it.
2. **A real-world result.** If you ran one of these on your own data and the numbers in
   its README don't match what you saw, open an issue with what you saw. Several READMEs
   say plainly that they were measured on generated data; a real measurement is the most
   useful thing anyone can add.
3. **A fix with a test.** Each repo's README has a Development section with the exact
   commands. CI runs the same ones.

## Never post personal data

Several of these tools exist because the data they handle is sensitive: customer chats,
Indian ID numbers, phone numbers, order exports. Before you attach a sample to an issue,
replace names, numbers and addresses. [nakli](https://github.com/yashere69/nakli) generates
fake ones that are safe to share, and [parda](https://github.com/yashere69/parda) can find
the ones you missed. If a bug only reproduces with real data, say so and we'll find another
way.

## Before a pull request

- For anything bigger than a bug fix, open an issue first. These tools are kept small on
  purpose, and a feature that makes sense in general may not fit one of them.
- Files under `results/` are generated by a script in `tools/`, named at the top of the
  file. Rerun the script; don't edit the output by hand.
- A change to behaviour gets a line in the CHANGELOG. Releases are cut by bumping the
  version in `pyproject.toml` with a matching CHANGELOG section; a workflow then tags the
  release and publishes its notes, so there's no separate release step to forget.
- `ruff check`, `ruff format --check`, `mypy src` and `pytest` should pass, on Python 3.11
  or later.

Security problems go through the process in [SECURITY.md](SECURITY.md), not an issue.
